DATACLEANING_AI — Complete Project Handoff (Version 2)
Project Name

DATACLEANING_AI

Tagline

AI-powered Multi-Agent Data Cleaning & Preprocessing System using LangGraph, LangChain, Gemini, Pandas, and Scikit-Learn.

Project Vision

The goal is to build an autonomous AI Data Engineering Assistant that converts messy datasets into machine-learning-ready datasets.

Instead of manually writing preprocessing code, the system should:

Analyze any CSV dataset.
Detect data quality issues.
Decide the best preprocessing strategy.
Generate Python preprocessing code.
Execute that code safely.
Validate the results.
Produce a cleaned dataset and detailed reports.

This is not just a machine learning project—it is an AI Engineering / Agentic AI project.

PROJECT GOAL

Build a production-quality Multi-Agent AI Data Cleaning System that autonomously converts messy tabular datasets into machine-learning-ready datasets.

CURRENT ARCHITECTURE

The project uses LangGraph StateGraph.

Pipeline:

Inspector
↓

Planner
↓

Coder
↓

Reviewer

Inspector performs deterministic dataset analysis using pandas.

Planner consumes the inspection report and creates structured preprocessing actions.

Coder uses Gemini through LangChain to generate executable preprocessing code.

Reviewer executes the generated code and validates the cleaned DataFrame.

CURRENT STATUS

The Inspector has already been upgraded to produce a rich structured report including shape, datatypes, missing values, duplicate rows/columns, constant columns, high-cardinality columns, numeric summaries, outlier detection, memory usage, empty strings, and possible datetime columns.

The Planner has been redesigned conceptually to output structured actions (dataset_actions and column_actions with reasons), but the pipeline is not yet fully synchronized.

The Coder still expects the old Planner format and must be updated to consume the new structured plan and the richer inspection report.

The Reviewer should validate execution success, DataFrame integrity, improvements in missing values and duplicates, and return structured validation results.

The LangGraph architecture itself should remain unchanged unless there is a compelling engineering reason.

IMMEDIATE OBJECTIVE

Refactor the agents so they all use a consistent shared state and communicate using compatible data structures.

Do not redesign the overall workflow.

After compatibility is restored, implement:
- retry loop from Reviewer back to Coder,
- structured logging,
- comprehensive tests,
- production-quality documentation,
- and a simple Streamlit interface.

When proposing code changes:
1. Preserve modularity.
2. Prefer deterministic logic where possible.
3. Use the LLM only where reasoning or code generation adds value.
4. Explain any interface changes between agents.
5. Provide complete updated files rather than isolated snippets when practical.
6. Consider maintainability, testing, and production-readiness throughout.
